# 贡献约定

生产代码在 `src` 和 `include/msys_compat`，公开测试与夹具在 `tests`。修改应优先保持职责清楚、调用链短和栈占用可控，尤其注意 MSYS 管理的二级线程栈。agent 无 CRT、普通导入和 DllMain；不能随意引入依赖。

优先使用直接控制流和已有类型。仅为当前调用保留字段、参数和抽象；实验适配留在实验侧。失败应在调用边界明确处理，避免层层降级把失败包装成成功。

`docs` 仅保存长期维护的正式文档，入口为 `docs/README.md`。`docs/design.md` 是当前实现的唯一主设计文档；重要取舍记录到 `docs/decisions`，已接受 ADR 的决定变化时新增记录并注明替代关系。`CHANGELOG.md` 记录已落地的用户可见变更，不记录待办或实验计划。

演进计划集中在本地 `unused/notes/evolution.md`，与编号专题目录放在一起；完整调查过程、版本实验、失败记录和候选方案放在 `unused/notes/NN-topic/NN-subject.md`。正式文档和生产代码不依赖这些本地文件。方案实现后，在同一提交中更新当前设计、支持边界、相关测试与变更说明。

专题使用稳定的两位编号；专题内按演进顺序编号，每篇注明已实现、已替代、候选或待验证。阶段编号不等于产品或协议版本，不用文件改名制造不存在的实验日期。保留失败原因、替代方案及证据入口，重复的架构或使用说明用链接连接。历史命令应注明当时路径，当前复现命令集中在维护中的入口。

`build` 保存构建产物；`unused` 顶层仅保留 `notes`、`evidence`、`experiments`、`package`、`runtime`，两者均忽略。历史证据按专题归类，最新输出在 `evidence/current/<suite>`；固定失败基线不能被重跑覆盖。删除可重建缓存和重复验证副本前，保留有价值的源码、失败日志及清理记录。可提交的项目必须能在没有本地研究材料的全新检出中正常构建和测试；生产构建不依赖历史材料。不要提交安装包副本、运行时快照、机器私有策略或生成的测试输出。

保持以下约束：不修改 MSYS2/Git 分发包；按实际导入名识别；不占用 debug port/INT3 通道；无关原生进程不注入；新包无需目录预扫描。若新能力需要改变这些边界，先明确模式和影响，再实现，不能悄悄改变默认行为。

生产兼容层不得修改任何磁盘文件或目录 ACL，包括安装目录、兼容产物、工作目录和临时目录。不得为兼容而放宽原 restricted token 的身份、禁用 SID、restricting SID、权限、完整性等级或原有访问限制；不能换用权限更大的 token、向所有 restricting SID 补授通用访问，或借非受限进程代读/预开被拒绝资源。IPC 和 MSYS 进程/线程对象的兼容处理应基于原隔离策略，不能把文件或其他资源的拒绝变成放行。

只有明确的测试夹具可在独立受控目录中设置 ACL；这用于建立测试初始策略，不随产品安装，也不能作为生产部署依赖。真实环境原策略拒绝所需访问时，保留拒绝并记录未覆盖的兼容条件，继续寻找原权限范围内的方案。验收同时检查真实工作负载成功与原限制保留，不能靠放宽夹具权限掩盖生产阻碍。

按变更影响运行相关回归。识别、注入、hook、对象授权或地址布局变化需要 fork 与作用范围测试；控制台变化需要交互测试；正式发布前运行完整回归和分发包完整性比较。不要仅凭测试输出中的成功标记忽略错误诊断或退出码。

提交按可独立理解和验证的变化组织。首次纳入现有实现应与后续行为修复分开；诊断尚无明确结论时留在本地，得到最小修复后连同回归和文档一起提交。只暂存本次范围内的明确路径，不提交 `unused`、生成产物或机器状态。
